混在グループトーク審査フロー

審査ありのSOTA（SOTAのマネが審査アプリのトークルーム内で承認）と、審査なしのNovel Core（即反映）が同じグループトークで話すケースです。投稿はアーティスト用の別アプリから行います。アーティスト同士は審査待ちのテキストも見え、未審査の投稿への返信は大元の承認後に10秒ずつ続けて送られます。返信でない投稿はすぐ送られます。「シナリオ再生」で流れを確認できます。各画面は手で操作もできます。

イベントログ

ルール：承認後に続けて送る

  1. 送信日時は承認した時刻：今の仕様のまま。SOTAの投稿は承認された瞬間にトークの末尾に入る。
  2. 楽屋ビュー：アーティスト用アプリでは、同じグループの審査待ちのテキストが「未審査」付きで見える。ファンには見えない。
  3. 審査待ちへの返信は「承認後に送信」：紐づけるのは LINE の返信のように返信ボタンを使ったときだけ。普通に送った投稿（「自分もみんなありがとう」など）は紐づけないので、SOTAが否認されても消えない。Novel Coreが未審査の投稿に返信すると、その返信は送信待機中になる。SOTAの投稿は承認した時刻に送信され、返信はそこから10秒ずつ順にファンへ届く。ファンには必ず SOTSOTA → Novel Core の順で、会話らしい間で表示される。
  4. 大元が承認されるまで出さない：返信を先に承認しても、返信先（返信への返信なら大元）が承認されるまでは送信待機中のまま。大元が否認されると、連なる返信はすべて送信されず、それぞれの投稿者に戻る。
  5. 独立した投稿はすぐ送る：返信でない投稿は待たない。審査なしのテンポは落ちない。
  6. 否認されたら返信はNovel Coreに戻る：SOTAが否認されると、紐づいた返信は送信されない。黙って消さずにNovel Coreへ「送信されませんでした」と知らせ、「引用を外して送る／書き直す／破棄」を選んでもらう。
  7. 待ちはNovel Coreがいつでも解除できる：送信待機中の返信に「待たずに送る」を出す。審査が長引いたときの逃げ道になる。
  8. マネには待っている返信の数を見せる：未審査バブルの下に「この投稿の承認を待っている返信 ◯件」を出し、承認を急ぐ理由が分かるようにする。

現行デザインとの関係：マネアプリの「先に審査した投稿から送信されます」（承認順に送信）と、アーティスト側の「承認済・送信待機中」表示はそのまま使えます。追加するのは、審査なしアーティストの返信を審査待ちの投稿に紐づける部分と、否認時にその返信をNovel Coreに戻す部分です。

定例で決めたいこと

  • 否認されたときの返信の扱い：Novel Coreに戻して選んでもらう（この案）か、自動で破棄して通知だけにするか。
  • 送り方を2種類（通常／返信）にするか、3種類目として「SOTAの後に送る（引用なし・否認されても送る）」を加えるか。
  • マネが本文を編集して承認した場合：紐づいた返信をそのまま送るか、Novel Coreに確認するか。
  • 楽屋ビュー：審査前のテキストを他事務所のアーティストに見せてよいか（情報管理上の可否）。
  • フェス当日の運用：審査担当を張り付ける時間帯と通知の出し方。
